# Luna run (2026-10-11)

Second measurement of the same 21 frozen cases, on a different actor family, after the first round
found no net improvement for the first skill body. This round measures the **revised** skill body.

## Setup

- Actor: `openai/gpt-6-luna` at high reasoning effort, one fresh actor per case per arm, no context
  shared between cells.
- `baseline` read `agents/evals/global-rules.md` only; no skill file was named or provided.
- `assigned` read the same rules plus `agents/skills/review-comments-and-docs/SKILL.md` (sha256
  `6762267a…`, 1200 words) — the revised body, +37/−19 lines against the 991-word `fb7a8135…`
  measured in the [first round](./2026-10-11-deepseek-flash.md).
- Tasks, requirements and forbidden criteria are unchanged from the first round: the same
  [`../fixtures.json`](../fixtures.json), including the bounded no-change controls F07b and F12b.
- Both arms were sampled fresh. No 21-case Luna baseline existed before this round, so reusing
  samples was not available; the previous Luna evidence covered other cases and a different skill
  body.
- Each actor read only the fixture and evidence paths named in its task plus the rules above, ran no
  commands, and wrote only its assigned `runs/results/luna-<arm>-<case>.txt`. All 42 samples arrived
  and no protocol violation was observed.

## Grading

- Judge: `deepseek-official/deepseek-flash` at high reasoning effort — a different family from the
  actor. Per case the two samples were relabelled `sample_1`/`sample_2` in a digest-determined
  order, so the judge could not tell which arm produced which. A case passes only when every
  required criterion holds and no forbidden criterion is met.
- The judge was switched mid-round from `openai/gpt-6.1-sol` for throughput. Three cases had already
  been graded by sol and are kept as a cross-check: F02 both arms fail and F04 both arms pass, which
  the new judge reproduced. The sol F05 verdict was discarded (six requirement rows for five
  criteria) and F05 was graded by the new judge.
- Mechanical: byte-identity failures on F07 and F12 in both arms. The baseline arm also failed the
  bounded control F07b by rewriting the reference file, which the first round's DeepSeek baseline
  did not do; the assigned arm kept F07b byte-identical.
- Two grading defects are recorded rather than hidden. The F16 prompt points at the case's target
  path `F16-guide.md`, which does not exist because the case creates the document; the judge graded
  the samples' own `<artifact>` blocks instead, and both arms pass there either way. F03's second
  criterion can be read strictly (the dated soak result must survive in the revised record) or
  loosely (it may remain only in the untouched log index); the strict reading was applied to both
  samples and both fail.

The arms agree on 16 of 21 cases: 12 pass in both and 4 fail in both. They disagree on five:

- F07b, assigned better: the baseline arm added an introduction and a new "what the evidence
  establishes" section to a reference the case requires to stay byte-identical, and reported a
  fabricated gap that the fixture already covers. The assigned arm left the file unchanged.
- F08, assigned better: the baseline findings never say that the metrics-server crash loop was
  removed as out of scope, so the artifact's edit is unreported. The assigned arm names the removal.
- F11, assigned better: the baseline arm turned the source's dated `TODO(2026-06-02)` into an
  undated open follow-up, losing the date the case requires to survive. The assigned arm kept it.
- F18, assigned better: the baseline arm never states the review's own scope — it never says that no
  runtime action or reproduction was performed. The assigned arm states it.
- F05, baseline better: the assigned findings narrate the corrected setting but never flag that the
  old comments presented the reverted 42 s value as active, nor what the dated photograph actually
  documents.

The five failure modes this revision targeted were F01, F04, F08, F11 and F17. On Luna the assigned
arm passes all five; F08 and F11 are net wins over the baseline arm, while F01, F04 and F17 were
already passing for both arms here.

The shared failures are F02 (the Auto baseline row is dropped in both arms), F03 (neither arm keeps
the dated soak result), the two ambiguous no-change controls F07 and F12, and F09, where the
baseline invents escalation triggers and the assigned arm drops the purpose statement.

## Skill iterations

The counters above measure the second skill body. Two further bodies were measured the same way: the
same frozen criteria, the same unchanged baseline samples, one fresh assigned-arm actor per case,
and the same blind judge.

| iteration    | skill body  | words | baseline vs assigned |
| ------------ | ----------- | ----- | -------------------- |
| — (this run) | `6762267a…` | 1200  | 12/21 vs 15/21       |
| 1            | `833319cf…` | 1348  | 13/21 vs 17/21       |
| 2            | `2b2fbd50…` | 1427  | pending              |

Iteration 1 added four rules drawn from the first run's failures: a comparison-point row (`Auto`, a
vendor default, an unmeasured baseline) and a dated result are content that survives where the
original stated it; a procedure keeps the purpose or trigger that tells a reader when to run it; a
report states the discrepancy it found rather than only the corrected state; and the close-out gate
checks all three. It fixed F02, F05 and F09 and took the assigned arm to 17/21. F16 regressed in the
same iteration and became the only case the baseline arm won.

Iteration 2 targeted the two remaining real failures: F03, where a dated verification the evidence
records has to be named in the record rather than left in the separate log index, and F16, where a
current value states its provenance when that changes how the reader should use it.

Two criteria were read two ways by different graders of the same judge model: F03's requirement 2
and F11's requirement 2. Both were re-graded under one pinned strict reading — the dated record must
appear in the revised artifact — applied to every round, so the counters compare the same test.

F07 and F12 are criterion-ambiguity controls. No iteration touched them, and no criterion was
changed at any point.

## Limits

- One sample per cell. A three-case lead is not a stable estimate, and these counts describe this
  frozen batch rather than a rate.
- Two rounds changed two things at once — the skill body (rev1 → rev2) and the actor family
  (DeepSeek-V41-Flash → gpt-6-luna). They do not isolate which of the two produced the difference:
  the same revision has not yet been measured on the first actor family.
- The judge here (`deepseek-flash`) is also one of the actor models used in this study. Its verdicts
  are blind to the arm and the samples under judgment are Luna's, which limits but does not remove
  the self-preference question; the pending DeepSeek re-measurement inherits it directly.
- Close calls rest on single criterion readings: F05, F08, F11 and F18 each turn on one requirement,
  and F07b's baseline failure is one byte-identity comparison.
- Samples, task files and per-criterion rows are generated locally and not committed (see
  [`../.gitignore`](../.gitignore)), so reproducing a number means rerunning the comparison.
- The run measures the skill body only. Automatic discovery, real editing sessions and other models
  are separate tests and remain unmeasured.
